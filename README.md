# LynShred 2.3.0

LynShred 是一款基于 **Tauri + Rust** 的图形化文件安全粉碎工具，提供可靠的物理级文件覆写删除功能。

## 功能特性

### 三种擦除算法

| 算法 | 遍数 | 覆写模式 | 说明 |
|---|---|---|---|
| **US Navy (3 passes)** | 3 | 全 `0x00` → 全 `0xFF` → 随机 | 快速擦除，覆盖基本数据残留 |
| **DoD 5220.22-M (7 passes)** | 7 | 随机 → 全0 → 全0 → 全1 → 随机 → 全0 → 随机 | 符合美国国防部标准，平衡速度与安全性 |
| **Gutmann (35 passes)** | 35 | 4遍随机 → 27遍特定字节模式 → 4遍随机 | 覆盖所有常见编码方式的磁道残留，最彻底的软件擦除方案 |

### 存储介质检测

- 自动检测文件所在驱动器是否为**固态硬盘（SSD）**
- 优先通过 `IOCTL_STORAGE_QUERY_PROPERTY`（Seek Penalty 查询）直接询问卷设备，**无需管理员权限**
- 查询不支持时回退到 Windows `fsutil volume disktype` 命令（需管理员）
- 检测到 SSD 时会弹出风险提示，告知用户磨损均衡机制可能导致覆写失效

### 目录树彻底清理（2.3.0 修复）

早期版本在添加文件夹时只把**文件**收集进清单，目录条目从未被记录，因此粉碎完成后会留下一整棵空目录树。2.3.0 重写了这部分：

- **不再依赖文件清单**：以「目标」为单位（文件 / 文件夹 / 整卷），文件夹与卷在列表中只占一行
- **后序遍历删除**：用显式栈对目录树做后序遍历，文件全部粉碎后自底向上逐个删除目录，最终连根目录一并移除
- **残留复核**：粉碎结束后重新扫描目标路径，任何仍然存在的条目都会逐条列出，不会静默忽略
- **如实报告失败**：被占用或无权限的文件不再被当作「已粉碎」统计，而是进入失败列表并在结果窗口中展示
- **超长路径**：删除与遍历统一走 `\\?\` 前缀，突破 260 字符的 `MAX_PATH` 限制

### 全盘粉碎（2.3.0 新增）

支持对指定的卷（盘符）执行整盘粉碎，卷按**物理磁盘**分组展示，可整盘勾选。

| | 文件夹粉碎 | 全盘粉碎 |
|---|---|---|
| 作用范围 | 选中的那一个目录树 | 整个卷根 `X://` 及其下全部内容 |
| 是否删除根 | 是，文件夹本身一并删除 | 否，保留卷根与盘符 |
| 空闲空间覆写 | 不支持 | 可选，用随机数据填满并覆写整卷空闲空间 |
| 系统保留区 | 不涉及 | 跳过 `System Volume Information` |
| 禁止对象 | 系统关键目录（`Windows`、`Program Files` 等） | 系统盘、本程序所在的卷 |

- 卷上的全部文件与子目录都会被删除（含隐藏文件、回收站内容）
- 被系统占用的文件（`pagefile.sys`、`hiberfil.sys`、运行中的进程文件）无法删除，会在结果中逐条列出，不会假装成功
- 空闲空间覆写采用**填充文件**策略：只会占用文件系统判定为空闲的簇，不会触碰任何已用数据，因此不可能损坏卷结构
- 不格式化、不修改分区表

### 用户界面

- **拖放支持**：直接将文件或文件夹拖入窗口即可添加
- **批量操作**：支持添加文件、添加文件夹（递归遍历）、多选移除
- **目标视图**：文件夹与卷以单行呈现，附带文件数量与总大小，不会因目录过大而卡顿
- **实时进度**：后台异步粉碎，进度条与当前处理文件实时反馈，支持随时取消
- **操作确认**：每次执行前弹出二次确认；全盘粉碎额外进行两次强确认

### 技术特性

- **异步架构**：粉碎操作在独立线程中运行，界面始终流畅
- **线程安全**：通过 `AtomicBool` 实现取消标志，无锁竞争；工作线程 panic 不会导致应用锁死
- **强制刷盘**：每遍写入后调用 `sync_all()` 确保数据落盘
- **读回验证**：首个确定性图案遍写入后读回校验，确认覆写确实落盘
- **分块写入**：512 KiB 分块，兼顾性能和取消响应速度

### 安全防护

**目标边界**

- **链接不跟随**：目录遍历时跳过符号链接 / NTFS junction，只摘除链接条目本身；根目录若是链接则直接拒绝（`read_dir` 会穿过 junction，等于越界删除）
- **打开时不解析重解析点**：覆写文件使用 `FILE_FLAG_OPEN_REPARSE_POINT`，即使路径在遍历后被替换为链接，也只打开链接本身
- **执行前重新校验**：从"加入列表"到"开始处理"之间目标可能被替换，执行前会重新确认一次（链接、系统目录、系统盘）
- **路径规范化校验**：拒绝以空格/点结尾的成分与 Windows 保留设备名（`con`、`nul` 等），避免剥掉 `\\?\` 前缀后指向另一个对象

**系统保护（不依赖环境变量）**

- **权威路径**：系统关键目录取自 `GetWindowsDirectoryW` 与 `SHGetFolderPathW`，不再读 `SystemRoot` / `ProgramFiles` 等可被伪造的环境变量
- **系统盘判定**：以 Windows 目录所在卷为准，并额外探测卷根特征文件（`Windows\System32\ntoskrnl.exe` 等），覆盖"Windows 装在非 C 盘"的情况
- **保守拒绝**：取不到权威路径时判定为关键路径，宁可拒绝也不误删

**擦除过程**

- **文件名冲刷**：覆写前连续 3 次随机重命名，降低原文件名在目录项 / MFT 中的取证残留
- **NTFS ADS 擦除**：枚举并覆写备用数据流，按流自身长度写入
- **填充文件安全**：覆写空闲空间时使用随机文件名 + `create_new`（绝不复用既有文件）+ 不跟随链接，并清理上次崩溃残留

**其它**

- **最小权限**：仅开放 `dialog` 的 `open` / `ask` / `confirm` / `message`，`shell.open` 与全部 `fs` 能力关闭
- **CSP 收紧**：`default-src 'self'` 之外补齐 `object-src 'none'`、`base-uri 'none'`、`frame-ancestors 'none'`、`form-action 'none'`
- **路径脱敏**：界面与结果面板把 `Users` / `home` 下的账户名替换为 `<用户>`，避免截图泄露本机用户名
- **依赖审计**：`cargo audit` 可复核已知漏洞
- **可执行文件解析**：`fsutil` 通过 `GetSystemDirectoryW` 取绝对路径调用，不按 `PATH` 查找

## 构建方法

### 环境要求

- Rust 工具链 (edition 2021)
- Windows (当前仅支持 Windows 平台)

### 编译

```bash
# Release 构建（当前架构）
cargo build --release
# 产物：target/release/LynShred.exe
```

### 32 / 64 位双架构构建

Windows 可执行文件的位数记录在 PE 头中，**一个 exe 无法同时是 32 位与 64 位**，
因此"通用版本"需要分别产出两个二进制，再放进同一个分发包：

```bash
# 一次性添加 32 位目标（只需执行一次）
rustup target add i686-pc-windows-msvc

# 64 位
cargo build --release --target x86_64-pc-windows-msvc
# 32 位
cargo build --release --target i686-pc-windows-msvc

# 汇编到一个目录
mkdir -p dist
cp target/x86_64-pc-windows-msvc/release/LynShred.exe dist/LynShred-2.3.0-x64.exe
cp target/i686-pc-windows-msvc/release/LynShred.exe   dist/LynShred-2.3.0-x86.exe
```

| 产物 | 架构 | 大小 | 适用 |
|---|---|---|---|
| `LynShred-2.3.0-x64.exe` | PE32+ x86-64 | 4.0 MB | Windows 10/11 主流设备 |
| `LynShred-2.3.0-x86.exe` | PE32 i386 | 3.4 MB | 32 位系统；也可在 64 位系统上通过 WOW64 运行 |

32 位构建需要 MSVC 的 x86 库（`VC\Tools\MSVC\<ver>\lib\x86`），安装 Visual Studio 时勾选「使用 C++ 的桌面开发」即可获得。

> 32 位进程地址空间为 4 GB，因此粉碎超大文件时相关尺寸计算统一使用 `u64`（见 `wipe.rs`），避免 `usize` 截断导致只覆写了文件的一部分。

两种架构均需系统已安装 **WebView2 运行时**（Windows 10 1803+ / Windows 11 通常自带）。

## 使用说明

1. 运行 `LynShred.exe`
2. 通过 **添加文件**、**添加文件夹** 按钮或直接拖放文件到窗口中
3. 如需整盘处理，点击 **全盘粉碎**，在弹出的面板中按物理磁盘勾选目标卷，选择是否覆写空闲空间后加入列表
4. 在底部下拉菜单中选择擦除算法
5. 点击 **开始处理**
6. 如检测到 SSD 会弹出风险提示，确认后继续
7. 再次确认操作不可逆（全盘粉碎需连续确认两次）
8. 等待进度条完成，结果窗口会列出未能处理的文件与残留项

> **注意**：粉碎操作不可逆，请务必确认文件已不需要再执行。

## 技术细节

### 覆写流程

1. 去除只读 / 隐藏 / 系统属性后，以读写模式 (`r+b`) 打开文件（缓解 TOCTOU）
2. 枚举并擦除 NTFS 备用数据流 (ADS)
3. 连续 3 次随机重命名，冲刷目录项中的原文件名
4. 按选定算法的模式序列逐遍写入数据
5. 每遍写入后调用 `sync_all()` 强制刷入物理介质；首个确定性遍读回验证
6. 覆写完毕后再次随机重命名并删除文件，同步父目录
7. 该目录下所有文件处理完后，自底向上删除每一层目录，直至根目录（文件夹模式）

### 失败与残留的界定

- 文件被占用、无权限、只读介质等原因无法覆写时，记入 `filesFailed`，**不会**被计为成功
- 因上述失败文件导致目录无法清空时，记入 `residual`，并在结果窗口中展示完整路径
- 取消操作时不再删除任何目录，避免出现「目录没了、文件还在」的中间状态

### SSD 风险说明

现代 SSD 使用磨损均衡 (Wear Leveling) 和垃圾回收 (Garbage Collection) 技术，操作系统对某个逻辑扇区的覆写操作不一定映射到相同的物理闪存单元。因此：

- 对于 SSD 上的文件，普通覆写删除**可能无法彻底清除原始数据**
- 针对高度敏感的数据，建议使用全盘加密 (如 BitLocker) 或物理销毁

### Gutmann 模式

原始的 Gutmann 算法专为 MFM/RLL 编码的传统硬盘设计，35 遍覆盖包括：

- 前 4 遍：随机数据
- 中间 27 遍：特定字节模式 (0x55, 0xAA, 0x92, 0x49 等)
- 后 4 遍：随机数据
